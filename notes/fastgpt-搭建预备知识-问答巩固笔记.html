FastGPT 搭建预备知识 · 问答巩固笔记

2026-08-17 基础概念

一、第一轮基础问答

====================================================

问题 1：PDF 里把变量比作什么？数据在节点之间是怎么"走"的？

我的回答：

变量比作一个贴着标签的箱子。数据在节点之间传递时，就是传递这个箱子。每个节点会打开箱子，看是不是自己需要的变量，如果是就拆出来用，然后再传递到下一个地方去。

老师修正：

方向正确，但更精确的说法是：

  • 变量 = 贴了标签的盒子
  • 节点之间传递的是"对这个盒子的引用"
  • 后面的节点不需要"打开每个盒子检查"，而是直接按标签名字去拿
  • 比如节点 3 写 {{用户问题}}，就是在说："我要用标签为'用户问题'的那个盒子里的内容"

问题 2：双花括号 {{用户问题}} 是什么意思？真正发送请求的时候会变成什么？

我的回答：

双花括号意思是把里面的变量取出来。真正发送请求的时候会变成 HTTP 请求格式。

老师修正：

方向正确，但"变成 HTTP 请求格式"表述不够准确。它应该变成变量里装的实际文本。

例如：

  • 配置时："{{用户问题}}"
  • 发送时："生成麦嘉雷尔SWITCH;WLAN项目的出项合同"

问题 3：为什么 Body 里要写成 "{{partyAName}}"（带引号），而不是 {{partyAName}}（不带引号）？

我的回答：

Body 里面的字符都必须要带引号。因为 partyAName 这个变量属于文本，所以必须带引号。如果漏了引号就识别不出来了。

老师评价：

完全正确。partyAName 是 string（文本）类型，JSON 里文本必须带双引号。漏了引号，接口解析 JSON 时会报错。

问题 4：HTTP 状态码 200 和 JSON 里的 ok 字段有什么区别？

我的回答：

状态码 200 表示接收正常。JSON 里的 ok 表示成功。如果只返回状态码 200 但 JSON 里是 false，还是失败了。必须两个都行才行。

老师评价：

完全正确。

  • 200 = 网络层面正常送到了
  • ok = "true" = 业务层面真正办成了
  • 200 + ok = "false" 是可能的，比如材料缺失

问题 5：为什么用 POST 而不是 GET？

我的回答：

GET 不是带着自己的文件包去的，它只是向接口询问，没有带着自己的东西去询问，所以无法传递上游的变量。POST 是带着自己的变量去询问的，所以使用 POST。

老师评价：

核心抓对了。补充一句：

  • GET：像"问一句现在几点"，只能带少量参数在 URL 后面
  • POST：像"寄一个包裹"，可以带完整的 JSON 在 Body 里

合同生成需要带用户指令、8 个字段等一堆数据，所以必须用 POST。

问题 6：如果接口返回 {"code": 0, "data": {"ok": "true", "billingText": "合同内容"}}，data.billingText 取到的值是什么？

我的回答：

Data billingText 取到的值是 data 数据下的 billingText 的合同内容。

老师评价：

正确。data.billingText 就是取返回 JSON 中 data 对象下面的 billingText 字段。

问题 7：FastGPT 里的变量可以从哪三个地方来？

我的回答：

三个地方：自己设置的变量、系统设置的变量、自定义的变量。

老师修正：

方向对，但表述不够准确。PDF 里说的三个来源是：

| 来源 | 例子 | 说明 |

|----------------|----------------------------|----------------------------|

| 前方节点的输出 | billingText、partyAName | 上游节点产生的变量，最常用 |

| 系统变量 | {{appId}}、{{chatId}} | FastGPT 平台自动提供 |

| 全局变量 | 系统配置 → 全局变量里自定义 | 整个应用共享的固定参数 |

可以理解为：

  • 上游节点给的 = 动态传递来的
  • 系统变量 = 平台自带的
  • 全局变量 = 你自己配置好、整个应用都能用的

二、第二轮进阶问答

====================================================

问题 1：变量能跨节点用吗？

题目：

节点 A 产生了变量 fileUrl。节点 B 没有和节点 A 连起来（中间没有线），但节点 B 的配置里写了 {{fileUrl}}。运行时会怎样？为什么？

我的回答：

变量不能跨节点用。因为下一个节点只能接收上一个节点的变量。如果节点 A 产生的变量没有和节点 B 连起来，那就算 B 的配置里面写了节点 A 的变量，也无法传递。因为节点 B 只能接受上游已经连接的变量。

老师评价：

完全正确。变量不能跨节点使用，节点 B 只能引用上游并且已经连到自己的节点产生的变量。

问题 2：变量替换后的真实 Body 是什么？

题目：

已知：

  • userInput = "生成A项目的出项合同"
  • projectName = "A项目"

HTTP 节点的 Body 配置如下：

{

"instruction": "{{userInput}}",

"project": "{{projectName}}",

"count": 1

}

真正发出去的时候，Body 会变成什么样？

我的回答：

{

"instruction": "生成A项目的出项合同",

"project": "A项目",

"count": 1

}

老师评价：

完全正确。注意 count 是数字，没有引号，所以保持原样。只有 string 类型的变量替换后才需要带引号。

问题 3：200 不等于成功

题目：

HTTP 节点收到接口返回：

  • 状态码：200
  • 返回的 JSON：

{

"code": 500,

"data": {

"ok": "false",

"error": "缺少甲方税号"

}

}

请问：

  1. 网络层面成功了吗？
  2. 业务层面成功了吗？
  3. 判断器里应该怎么判断？

我的回答：

  1. 这个请求在网络上面成功了，因为显示的是 200 状态码，说明在网络层面已经接收了。
  2. 但是在业务层面没有成功，因为 ok 显示的是 false，原因是缺少甲方税号。
  3. 判断器里面应该判断 ok 等于 true 来走成功分支，判断 false 来走失败。

老师评价：

完全正确。额外补充：这个 JSON 里还有一个 code: 500，这是接口自己的业务错误码，不是 HTTP 状态码。有些接口会同时用 HTTP 状态码和内部 code 字段两层来判断。

三、易错点总结

====================================================

  1. {{变量}} vs "{{变量}}"
  • {{变量}}：取这个变量的值
  • "{{变量}}"：取这个变量的值，并且这个值是字符串，要加引号

在 JSON 里，字符串必须加引号。

  1. 节点只能引用连到自己上游的变量

没连线的节点之间不能传递变量。

  1. 变量在节点执行的那一瞬间被替换

配置时看到的是 {{用户问题}}，真正运行时会变成真实文本。

  1. HTTP 200 ≠ 业务成功

还要看接口返回的 JSON 里 ok 字段是不是 "true"。

  1. 状态码 vs 业务码
  • HTTP 状态码：200、4xx、5xx
  • 接口内部 code：有些接口会自己再定义一个 code 字段
  • ok 字段：业务是否成功
  1. POST 才能带 Body

GET 没有 Body，只能把少量参数挂在 URL 后面。

需要传递复杂数据或上游变量时，必须用 POST。

四、下阶段学习建议

====================================================

  1. 对照真实搭建手册，逐个节点看配置
  2. 重点理解 HTTP 节点里的 Body 和返回值解析表格
  3. 动手调试一次，看实际发出的请求和返回的 JSON
